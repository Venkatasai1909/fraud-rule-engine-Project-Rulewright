## Where AI output needed review or correction

- **Completion claims versus evidence:** Generated implementation notes can describe intended behaviour, but they do not prove that Maven tests, Redis integration, two-instance propagation, or the load test passed. These must be executed and their real output recorded before submission.
- **Requirement interpretation:** The assignment requires behavioural features to use the same `{ "field": ... }` leaf format as ordinary fields. Any separate feature-specific syntax must not replace that required format. Verify the actual parser and tests support the required syntax.
- **Latency assumptions:** A fast in-memory matcher does not prove a fast end-to-end authorization path. Database persistence, idempotency coordination, Redis calls, and connection-pool contention must be included in the benchmark.
- **Framework constraint:** The assignment specifies Spring Boot 3.x. The inspected project POM used Spring Boot 4.1.2 at the time this disclosure was drafted. This is a compatibility/compliance item to resolve; do not describe the project as Boot 3.x until the POM is changed and the build is verified.
- **Documentation accuracy:** Architecture diagrams and run instructions are explanatory. They must be checked against the final code, environment variable names, endpoints, and deployment setup.
